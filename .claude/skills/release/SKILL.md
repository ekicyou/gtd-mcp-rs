# リリース（crates.io）

## Core Task

`/release [X.Y.Z]` の 1 回で、`gtd-mcp` の次の版を crates.io に出し、日本語の最終報告を 1 つ出す。引数なしは旧版の 3 つ目の数字に 1 を足す。引数は `X.Y.Z` か `vX.Y.Z`。公開済みの版の見どころの直しを頼まれたときは、段を回さず「見どころの直し」だけを行う。

**正本は同じディレクトリの [`procedure.md`](procedure.md)。** 段・コマンド・判定・表・してはいけない事・止まり方はすべて `procedure.md` が正本で、この `SKILL.md` はその要約に過ぎない。食い違えば `procedure.md` に従う。実行の前に `procedure.md` を読む。

## 段の要約

| 段 | 名前 | 中身 |
|---|---|---|
| 0 | 再開の読み方 | 版上げ PR・リモートのタグ・作業木・先頭のコミットを読み、再開の表で始める段を決める |
| 1 | 前提の確かめ | 1.1 枝・作業木・main ／ 1.2 開いた PR ／ 1.3 旧版と前のタグ ／ 1.4 次の版 |
| 2 | 版上げと見どころ | 2.1 版上げ（`Cargo.toml`・`Cargo.lock`）／ 2.2 見どころ（`doc/release-notes/v{版}.md`） |
| 3 | 手元の確かめ | 3.1 差分の範囲 ／ 3.2 見どころの形 ／ 3.3 CI と同じ確かめ ／ 3.4 公開前の確かめ |
| 4 | 版上げ PR とマージ | 4.1 コミットと PR ／ 4.2 PR のファイル ／ 4.3 main の移動 ／ 4.4 squash マージ |
| 5 | タグ | 5.1 タグの確かめ ／ 5.2 タグの push |
| 6 | 公開の見守り | 6.1 走りの特定と待ち ／ 6.2 緑の判定 ／ 6.3 赤の扱い |
| 7 | 報告 | 日本語の最終報告を 1 つ |

## Rules

- **明示実行だけ**: 開発者が `/release` を打ったときだけ動く。会話の流れから自分で起動しない。
- **してはいけない事**: タグを動かさない・消さない。同じ版を二度出さない。`--tags`・`--follow-tags`・`--force`・`--admin`・main への直接 push をしない。手元から `cargo publish` しない（段 3.4 の `--dry-run` は除く）。`gh run rerun` など、走りを自分からやり直さない。版上げ PR に版上げ以外を混ぜない。
- **止まり方**: 順調な経路では承認を待たない。止まるのは、確かめが外れたとき・走りが赤のとき・手順に無い状態を見たとき・許可の判定にコマンドを断られたときだけ。断られたら言い換えず、別の道具で回避せず、そのコマンドと理由を示して止まる。止まったら止まった段・見えた事実・次に開発者が決めることを報告する。
- **外へ出るコマンドは単独の 1 行**: `git push`・`gh pr create`・`gh pr merge` は 1 回の呼び出しにつき、他のコマンドとつながない 1 行で実行する。
- **印字の禁止**: リモートの接続先 URL や認証情報を印字しない（`git remote -v` を使わない。`fetch`・`push`・`ls-remote` は `--quiet` で標準エラーを捨て、成否は終了コードと読み直しで決める）。
- **書き換えの禁止**: リリースの途中で Publish Workflow・既存のワークフロー・ソースコードを書き換えない（整形の自動修正もしない）。他の版の見どころと `RELEASE.md` も変えない。範囲外の問題は最終報告に書く。
- **進み具合のファイルを作らない**: 主文脈で実行し、サブエージェント・進み具合のファイル・記録用のコミットを作らない。再開は毎回、段 0 で事実を読み直して決める。
